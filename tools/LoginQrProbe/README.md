# LoginQrProbe —— 扫码登录真机验证探针

单元测试证明的是"按假响应能跑对"；本探针回答另一个问题：**真实接口是否与假设一致**。
它走一遍真实的取码 → 扫码 → 轮询 → 取用户信息 → 下载头像，逐步断言并产出脱敏报告。

## 怎么跑

```powershell
# 真机扫码验证（默认渲染二维码）
dotnet run --project tools/LoginQrProbe

# 网络需要代理时
dotnet run --project tools/LoginQrProbe -- --proxy http://127.0.0.1:7897

# 离线自检：不联网，用假响应验证探针自身逻辑
dotnet run --project tools/LoginQrProbe -- --offline
```

跑完的流程：

1. 取码并打印二维码内容与失效时刻；
2. 在终端渲染二维码 → **用哔哩哔哩手机客户端扫码并确认登录**；
3. 打印扫码状态变化（待扫码 → 待确认 → 已登录）；
4. 取回昵称、头像地址，再下载头像字节；
5. 汇总断言，可选写出脱敏报告。

> 扫码期间请勿录屏或共享屏幕：终端会显示二维码内容，等同于登录凭据的入口。

## 选项

| 选项 | 作用 |
| --- | --- |
| `--offline` | 只跑离线自检（7 个场景），不访问网络 |
| `--no-render` | 不渲染二维码，只打印内容（终端显示异常时自行生成二维码） |
| `--timeout <分钟>` | 整个流程的超时，默认 5 |
| `--proxy <地址>` | 显式代理；默认跟随系统代理设置 |
| `--output <路径>` | 写出脱敏报告（Markdown） |
| `--verbose` | 额外打印服务内部日志（排查用） |

## 退出码

| 码 | 含义 |
| --- | --- |
| 0 | 全部断言通过 |
| 1 | 登录完成但有断言失败（见输出里的 FAIL 列表） |
| 2 | 取码失败 / 超时 / 被 Ctrl+C 取消 |
| 64 | 参数用法错误 |

## 断言清单

| # | 断言 | 失败通常意味着 |
| --- | --- | --- |
| 1 | 二维码内容是合法的 bilibili https 登录地址 | 接口形态变了 |
| 2 | 有效期落在 2~5 分钟 | 与文档假设不符，需更新参数 |
| 3 | 轮询终局为 `Succeeded` | 本次没扫成（超时/网络），非代码问题 |
| 4 | 凭据三件套齐备 | `Set-Cookie` 解析或 302/200 形态判定有问题 |
| 5 | `nav` 返回昵称 | **Cookie 域不对**（应为 `bilibili.com`，不是 `passport.bilibili.com`） |
| 6 | 头像下载到非空字节 | 缺 `Referer` 导致 CDN 403 |

## 关于二维码渲染

探针自带一个极简编码器（`QrEncoder.cs`，版本 5-L、字节模式，约 106 字节容量），
不引第三方包，保证离线可用。它的正确性已通过独立解码器往返验证（含 BCH 格式串与 Reed-Solomon 自洽性检查）。

终端渲染优先用 ANSI 反显 + 半块字符（紧凑且不受配色影响）；
输出被重定向或终端不支持 ANSI 时，退化为逐模块的 `██` / 空格渲染，**一个模块都不合并**，避免扫不出来。

若终端渲染始终不理想，用 `--no-render` 拿到内容后自行生成二维码即可 —— 验证的重点是登录链路，不是渲染。

## 离线还原

本目录自带 `NuGet.config` 指向仓库内被忽略的离线包源，无网络也能 `dotnet run`。
该包源由脚本生成：

```powershell
pwsh -File tools/LoginQrProbe/rebuild-offline-feed.ps1
```

联网环境删掉本目录的 `NuGet.config` 即改走官方源。
