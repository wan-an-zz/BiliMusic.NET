# 导航控件文档

> 覆盖范围：`DesktopSideNavControl`（桌面端侧边导航）与 `BottomNavControl`（安卓端底部导航）**两个控件**。
> 不含页面内容、不含窗口外壳、不含业务页面 —— 那些各自的文档负责。
>
> 图标路径资源 `Styles/Icons.axaml` 与数据模型 `NavItem` / `NavIcon` 作为二者共同的基础，一并说明。

---

## 1. 技术栈

| 项 | 取值 |
| --- | --- |
| 运行时 | .NET 10 |
| UI 框架 | Avalonia 12.1.2（`AvaloniaUseCompiledBindingsByDefault=true`） |
| 列表控件 | `ItemsControl` + `ItemTemplate`（模板由数据驱动，控件内无具名按钮） |
| 内容渲染 | `TransitioningContentControl` + `CrossFade`，经 `Application.DataTemplates` 中的 `ViewLocator` 解析 ViewModel → View |
| MVVM | CommunityToolkit.Mvvm（`ObservableObject` / `RelayCommand`） |
| 图标 | `PathIcon` + `StreamGeometry` 资源；地址由 `NavIcon` 门面读取 |
| 依赖注入 | `Microsoft.Extensions.DependencyInjection`（`MainViewModel` 单例，导航项集合在构造期构建） |

## 2. 两个控件对照

| 维度 | `DesktopSideNavControl` | `BottomNavControl` |
| --- | --- | --- |
| 位置 | `BiliMusicDotNet.Desktop/Controls/` | `BiliMusicDotNet.Android/Controls/` |
| 使用方 | `DesktopMainWindow`（`Window`） | `AndroidMainView`（`UserControl`） |
| 形态 | 左栏 64 宽图标导航 + 右侧内容卡片 | 上方内容区 + 底部 64 高标签栏 |
| 数据入口 | `ItemsResource`（**单份集合**） | `ItemsResource`（**同一份集合**） |
| 分段 | **控件内部**按 `NavItem.Group` 拆成两段：上方 B 组 / 底部 A 组 | 不分段，直接进 `UniformGrid` |
| 标签文字 | 不显示（纯图标） | 显示（图标 + `Label`） |
| 选中指示器 | 48×48 渐变圆角块，在图标**下层**，靠 `Margin.Top` 位移 | 24×3 圆角条，在标签**底部**，靠 `Opacity` + `scaleX` |
| 动画 | B 组内部平移 / 涉及 A 组淡出→瞬移→淡入 | 纯过渡：`scale(1.15)` + 指示器展开 |
| 舵式按钮 | 无 | 无 |
| 占位项 | 无 | 无 |

两者**都只依赖 `BiliMusicDotNet.Models.Navigation`**（`NavItem` / `NavGroup`），不引用 `ViewModels`、`Services`、`Abstracts`。

## 3. 分层与数据流

```
Styles/Icons.axaml                 图标路径资源（StreamGeometry，key 如 IconHome）
        │  NavIcon.Resolve(key) 按 key 取回 Geometry
        ▼
MainViewModel.Views                ObservableCollection<NavItem>
        │                          每项 = Label + Icon + Group + Content(ViewModel)
        ├──────────────► DesktopSideNavControl   ─┐
        └──────────────► BottomNavControl        ─┤ 同一份集合，两个控件各自消费
                                                 │
                      SelectedItem.Content ──────┴─► ContentPresenter
                                                        │ Application.DataTemplates
                                                        ▼
                                                   ViewLocator → View
```

**关键点**：`ItemsResource` 是**同一份集合实例**。桌面控件按 `Group` 拆成上方 B 组与底部 A 组渲染；安卓控件把 `A` 和 `B` 混在一起按原顺序铺进 `UniformGrid`（安卓端不关心分组语义）。

因此**导航项在集合里的顺序**决定安卓端的标签排布，而桌面端的排布由 `Group` 决定。两者可以同时成立：`Group` 只对桌面端有意义。

## 4. `DesktopSideNavControl` API

命名空间 `BiliMusicDotNet.Desktop.Controls`。

| 成员 | 类型 | 说明 |
| --- | --- | --- |
| `ItemsResource` | `ObservableCollection<NavItem>` | 导航项集合。**唯一数据入口**，控件内部按 `Group` 分两段：上方 B 组与底部 A 组 |
| `ItemTemplate` | `IDataTemplate?` | 导航项外观。不设置时用控件内置模板（纯图标 + `Button`） |
| `SelectedIndex` | `int`，`TwoWay`，默认 0 | 选中项的**全局索引**，按「上方 B 组 → 底部 A 组」拼接计数。越界不抛异常，仅表现为无选中项 |
| `SelectedItem` | `NavItem?`，只读 | 当前选中项；右侧内容区渲染它的 `Content` |
| `SelectItemCommand` | `ICommand` | 内置模板点击入口，参数为该 `NavItem` |
| `SelectItem(NavItem?)` | 方法 | 同上，供代码直接调用 |
| `ContentArea` | `Panel` | 右侧内容面板。宿主可追加子元素（如自实现标题栏），**后加的画在上层** |
| `Sidebar` | `Border` | 导航栏外框。宿主可覆盖其圆角 / 背景等外观 |

### 4.1 分段规则

按源集合顺序遍历，`Group == NavGroup.B` 的项全部进上方段，`Group == NavGroup.A` 的项全部进底部段，各自保持源顺序。`Group` 的默认值是 `B`，普通导航项默认进上方 B 段，只有需要钉底的项目才标 `A`。

因此布局形如 `[B…, 弹性空白, A…]`：B 组贴顶、A 组钉底；没有 A 项时底部段留空，没有 B 项时上方段留空。

### 4.2 全局索引 ↔ 段内位置

| 全局索引区间 | 落在哪一段 | 段内下标 |
| --- | --- | --- |
| `0 .. B.Count-1` | `GroupBItems` | 同值 |
| 其余 | `GroupAItems` | `全局 - B.Count` |

### 4.3 视觉结构

```
Grid  ColumnDefinitions="Auto,*"  ColumnSpacing="20"  Background=Transparent
├─ Border  SidebarHost                        ← 左栏
│    Background=White  CornerRadius=14  Width=64  Padding="10,14"  Margin="5,0,0,0"
│    BoxShadow="0 2 20 0 #0F000000"
│  └─ Grid  ContentGrid
│     ├─ Border Indicator          48×48  CornerRadius=14  Margin.Top 定位   ← 在图标下层
│     └─ Grid RowDefinitions="Auto,*,Auto"   ZIndex=1
│        ├─ Row0 ItemsControl GroupBItems       ← B 组（默认），间距由 nav-btn 的 Margin 提供
│        ├─ Row1 弹性空白（*）
│        └─ Row2 ItemsControl GroupAItems       ← A 组，被弹性空白钉到底部
└─ Grid  ContentAreaHost                      ← 右栏
   └─ Border ContentCard  CornerRadius=14  Background=White  BoxShadow="0 2 20 0 #0A000000"
      └─ TransitioningContentControl ContentHost  CrossFade 0.3s
```

**两栏之间的 20 `ColumnSpacing` 是刻意留出的透明空隙**：控件不绘制它，透出的是宿主（桌面端为窗口的玻璃面板）。宿主必须自己提供不透明或半透明背景，否则该处会露出桌面。

### 4.4 指示器定位

指示器的 `Margin.Top` 由**图标位置**反推，而不是按行高估算：

```
containerTop = Σ 从容器到 ContentGrid 的各级 Bounds.Y      ← 必须累加！
indicatorTop = containerTop + icon.Bounds.Y + (icon.Bounds.Height - 48) / 2
```

> **踩过的坑**：`Bounds.Y` 是**相对各自父级**的。B 段与 A 段各有 `ItemsControl → StackPanel` 层级，A 段还隔着弹性空白。若直接用 `container.Bounds.Y`，B 段凑巧正确（父级在 0），A 段会偏小 → 指示器落不到目标图标上。这就是 `OffsetFromContentGrid` 存在的原因。

重算时机：`LayoutUpdated` 的**首次布局**（`_lastHeight == 0 && Bounds.Height > 0`）与**高度变化 > 1** 时。

### 4.5 指示器动画状态机

按 `Group` 判断（`items[oldIndex].Group == NavGroup.A || items[newIndex].Group == NavGroup.A` 即涉及底部 A 组）：

| 源 → 目标 | 路径 | 时序 |
| --- | --- | --- |
| **涉及 A 组**（任一端是 A，含 A ↔ A） | `AnimateShrinkThenExpandAsync` | `Opacity = 0` → 等待 `FadePhaseDelayMs`(220ms) → `SetIndicatorPosition(新位置)` → 等待 220ms → `Opacity = 1` |
| **B ↔ B** | `AnimateSmoothTranslateAsync` | `Opacity = 1` → `SetIndicatorPosition(新位置)` → 等待 `TranslateDurationMs`(220ms) |

两段等待分别对应 XAML 里声明的过渡：

| 过渡 | 声明 |
| --- | --- |
| `Margin`（平移） | `ThicknessTransition Duration="0:0:0.25" Easing="CubicEaseInOut"` |
| `Opacity`（淡出淡入） | `DoubleTransition Duration="0:0:0.18"` |

> 涉及 A 组走淡出路径是因为指示器要翻越弹性空白跳到另一端，直接平移会**长距离掠过中间项**。淡出后瞬移再淡入，视觉上更干净。

### 4.6 变色时序（两阶段）

这是需求明确要求的行为，**不是**"选中即变色"：

| 时刻 | 旧图标 | 新图标 | 指示器 |
| --- | --- | --- | --- |
| 点击瞬间 | **立即变回 `#8e8e93`** | 保持灰色 | 开始淡出 / 平移 |
| 动画进行中 | 灰 | 灰 | 在途 |
| 动画结束 | 灰 | **变白 `White`** | 已到位 |

实现：`AnimateIndicator` 启动动画**之前**调 `DeselectItem(旧项)`；两个动画方法**结束之后**才调 `UpdateSelection()`（该方法统一写所有项的 `IsSelected` 并更新 `SelectedItem`）。

**图标颜色本身不参与过渡** —— `PathIcon.nav-icon` 没有 `BrushTransition`，颜色是瞬切的。变色与移动的"先后感"完全由上面这张时序表提供。

### 4.7 竞态与边界处理

| 场景 | 处理 |
| --- | --- |
| 快速连点 | 每次动画替换 `_animationCts` 并 `Cancel` 旧实例；被取消的动画在 `catch` 里**直接 return，不补色**，避免旧动画把颜色盖到已经过时的项上 |
| 集合变动 / 换源 | `ResetIndicatorToSelection()` 先 `Cancel()` 在途动画，再清缓存、重算位置、立即 `UpdateSelection()` |
| 索引越界（`SelectedIndex` 超出项数） | 不抛异常，`SelectedItem` 为 `null`，无任何项被标记选中 |
| 位置缓存缺失 | `AnimateIndicator` 退化为立即 `UpdateSelection()`（不播动画），避免留下"旧项已取消、新项未上色"的半成品状态 |
| `ItemsResource` 为空 | 位置缓存清空，指示器隐藏（`Opacity` 保持 1 但无位置可落），无异常 |

## 5. `BottomNavControl` API

命名空间 `BiliMusicDotNet.Android.Controls`。

| 成员 | 类型 | 说明 |
| --- | --- | --- |
| `ItemsResource` | `ObservableCollection<NavItem>` | 导航项集合，**顺序即标签顺序** |
| `ItemTemplate` | `IDataTemplate?` | 标签外观。不设置时用内置「图标 + 文字」模板 |
| `SelectedIndex` | `int`，`TwoWay`，默认 0 | 选中项索引。越界不抛异常 |
| `SelectedItem` | `NavItem?`，只读 | 当前选中项；上方内容区渲染它的 `Content` |
| `NavControlBackgroundColor` | `string`，默认 `#FFFFFF` | 导航栏背景色 |
| `SelectItemCommand` | `ICommand` | 内置模板点击入口，参数为该 `NavItem` |
| `SelectItem(NavItem?)` | 方法 | 同上，供代码直接调用 |

### 5.1 视觉结构

```
Grid RowDefinitions="*,Auto"
├─ Row0 TransitioningContentControl ContentHost   CrossFade 0.3s
└─ Row1 Grid  Height=64  ClipToBounds=False  VerticalAlignment=Bottom
   ├─ Border  Background={NavControlBackgroundColor}
   │          CornerRadius="20,20,0,0"   BoxShadow="0 -4 12 0 #1A000000"
   └─ ItemsControl TabItems
      └─ ItemsPanelTemplate: UniformGrid Rows=1        ← 等宽分布
      └─ ItemTemplate: Panel
         ├─ Button.tab-btn → StackPanel(图标 22×22 + 文字 10)
         └─ Border.tab-indicator                        ← 底部指示器
```

### 5.2 选中动画

与桌面端不同，安卓端**没有代码驱动的动画**，全部由 XAML 过渡完成：

| 元素 | 未选中 | 选中 | 过渡 |
| --- | --- | --- | --- |
| 图标 `tab-icon` | `#0c1627` | `#2e7bff` + `scale(1.15)` | 仅 `RenderTransform` 0.25s `CubicEaseOut`；**颜色瞬切** |
| 文字 `tab-label` | `#0c1627`，10px | `#2e7bff`，`SemiBold` | 无过渡，全部瞬切 |
| 指示器 `tab-indicator` | `Opacity=0`，`scaleX(0.2)` | `Opacity=1`，`scaleX(1)` | `Opacity` + `RenderTransform` 各 0.25s `CubicEaseOut` |
| 按钮 `tab-btn` | 透明底 | — | `:pressed` 时 `scale(0.95)` |

> **颜色不参与过渡**是有意为之：图标与文字应当在点击瞬间就变色，放大动画随后播放。曾一度给两者加了 `BrushTransition`，观感变成"动画放完颜色才到位"，已移除。

## 7. 最小使用示例

### 7.1 数据模型与图标

```csharp
using BiliMusicDotNet.Models.Navigation;

Views =
[
    new NavItem
    {
        Label = "首页",
        Icon = NavIcon.Resolve(NavIcon.Home),   // key 取自 Styles/Icons.axaml
        Group = NavGroup.B,                     // B 组 → 桌面端上方区块（默认）
        Content = homeViewModel,                // 由 ViewLocator 解析成 View
    },
    new NavItem
    {
        Label = "设置",
        Icon = NavIcon.Resolve(NavIcon.Settings),
        Group = NavGroup.A,                     // A 组 → 桌面端钉底
        Content = settingsViewModel,
    },
];
```

`NavItem` 的成员：`Label`、`Icon`（`Geometry?`）、`Group`（`NavGroup.A` / `B`）、`Content`（`ViewModelBase?`）、`IsSelected`（**由控件写入，业务侧不要手工赋值**）。

### 7.2 桌面端

```xml
<dc:DesktopSideNavControl ItemsResource="{Binding Views}"/>
```

需要自定义外观时提供模板：

```xml
<dc:DesktopSideNavControl ItemsResource="{Binding Views}">
    <dc:DesktopSideNavControl.ItemTemplate>
        <DataTemplate DataType="nav:NavItem">
            <Button Classes="nav-btn"
                    Command="{Binding $parent[dc:DesktopSideNavControl].SelectItemCommand}"
                    CommandParameter="{Binding}">
                <PathIcon Data="{Binding Icon}"/>
            </Button>
        </DataTemplate>
    </dc:DesktopSideNavControl.ItemTemplate>
</dc:DesktopSideNavControl>
```

> `$parent[...]` **必须带命名空间前缀**（`dc:`），否则报 `AVLN2000: Unable to resolve type`。

窗口需要叠标题栏时，往 `ContentArea` 追加（后加的画在上层）：

```csharp
SideNav.ContentArea.Children.Add(myTitleBar);
```

### 7.3 安卓端

```xml
<ac:BottomNavControl ItemsResource="{Binding Views}"
                     NavControlBackgroundColor="#FAFBFC"/>
```

### 7.4 图标资源

```xml
<!-- XAML 里直接用 -->
<PathIcon Data="{StaticResource IconHome}"/>
```

```csharp
// 代码里用门面取
Geometry? icon = NavIcon.Resolve(NavIcon.Home);
```

`Icons.axaml` 现有 key：`IconHome`、`IconSearch`、`IconUser`、`IconSettings`（对应 `NavIcon.Home/Search/User/Settings`）。

新增图标 = 在 `Styles/Icons.axaml` 加一条 `<StreamGeometry x:Key="...">`，并在 `NavIcon` 补一个常量。

## 8. 独立性契约

两个控件都满足以下约束，改代码时不要破坏：

| # | 约束 | 现状 |
| --- | --- | --- |
| 1 | 不引用 `ViewModels` / `Services` / `Abstracts` | 均只 `using BiliMusicDotNet.Models.Navigation` |
| 2 | 控件内无硬编码图标路径、无具名导航按钮、无固定项数 | 图标一律经 `NavItem.Icon` 注入 |
| 3 | 数据与外观全部外部注入 | `ItemsResource` + `ItemTemplate` |
| 4 | 空数据 / 越界安全 | 集合空、索引越界均静默短路，不抛异常 |
| 5 | 单向职责 | 只渲染与维护选中态，不创建 / 不销毁 / 不改集合内容（仅写元素的 `IsSelected`） |
| 6 | 可整体搬运 | 两控件互不引用，删掉任一个另一个不受影响 |

---

## 9. 依赖与约束

- **图标必须先经 `NavItem.Icon` 注入**。控件不会自己去查资源字典；`Icon` 为 `null` 时该按钮渲染为空，但点击区仍在。
- **`ItemTemplate` 是可选的**。不提供时用内置模板；内置模板已经包含 `Button` + 命令绑定，若你自写模板，**必须自己接上 `SelectItemCommand`**，否则点了没反应（这个坑踩过一次）。
- **`NavItem.IsSelected` 由控件写入**，业务侧赋值会被下一次 `UpdateSelection()` 覆盖。
- **桌面端两栏之间的 20 空隙是透明的**，需要宿主提供背景，否则露出桌面。
- **桌面端 A 组固定底部**：A 组为空时底部段留空、弹性空白仍在；多个 A 项按源顺序堆在底部区块。
- **安卓端 `tab-label` 未设置 `FontFamily`**，走平台默认字体；若要指定字体需另行引入字体资源。
- **`Group` 对安卓端无意义**，安卓端按集合顺序铺标签；同一个集合因此可以两端共用。
- **集合上限 64 项**（桌面端）/ 8 项（安卓端），超出部分被忽略，防止异常数据撑爆布局。

## 10. 非目标

- 舵式按钮（中央凸起按钮）及其覆盖层扩散动画 —— **已移除**；
- 占位项 `IsPlaceholder` —— 随舵式按钮一并移除；
- 窗口外壳（无边框、透明、标题栏）—— 由 `DesktopMainWindow` 负责，见桌面端窗口相关文档；
- 具体业务页面的内容 —— 由各自的 ViewModel / View 负责；
- iOS 端导航控件。

## 12. 待办 / 已知问题

- **运行时观感未经自动化验证**。`Avalonia.Headless` 在本机只有 12.0.1，与本项目 Avalonia 12.1.2 ABI 不兼容（一建 `Window` 即抛 `TypeLoadException: SetFrameThemeVariant`），因此两控件的动画、指示器落点、`ContentPresenter` 解析均只经过编译期校验与人工观感验收，**没有回归测试**。
- **`ContentArea` / `Sidebar` 是内部 `x:Name` 的对外暴露**，若将来重命名 XAML 里的 `x:Name`，需同步改这两个属性。
- **项容器数量依赖布局已完成**。`CalculateIndicatorPositions` 先 `UpdateLayout()` 再枚举容器；若某段使用虚拟化面板，容器的枚举顺序会失效（当前两段都是普通 `StackPanel`，不受影响）。
